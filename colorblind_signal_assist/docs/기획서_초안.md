## 1. 앱 한 줄 소개

**색·소리·작은 경고등에 의존하는 차량 정보를, 운전자 특성(색각이상·청각장애·저시력·주의력 저하)에 맞는 다른 감각으로 바꿔 전달하는 접근성 운전 보조 앱**

## 2. 기획 배경

자동차는 운전자에게 정보를 줄 때 **한 가지 감각에만 의존하는 경우가 많습니다.**

| 정보 | 의존하는 감각 | 받기 어려운 운전자 |
|---|---|---|
| 신호등 적·녹·황 | 색 | 색각이상 |
| 벨트 경고음, 방향지시등 똑딱 소리, 내비 음성 안내, 긴급차량 사이렌 | 소리 | 청각장애 |
| 계기판의 작은 경고등·아이콘 | 작은 시각 기호 | 저시력, 고령 |
| "방향지시등 껐나?", "뒷좌석 확인했나?" | 기억·주의 | 주의력 저하, 고령 |

대상 규모 (출처 있는 수치만 사용):
- **색각이상**: 아동·청소년 대상 전 세계 메타분석에서 남성 4.38%, 여성 0.64%로 추정됩니다(2025). 국내 초등학생 연구에서는 남학생 3.8%로 보고되었습니다(1999, 소규모 표본).
- **청각장애**: 2024년 말 등록장애인은 263만 1,356명이고 그중 청각장애가 16.8%입니다(보건복지부). 비율로 계산하면 약 44만 명입니다(추정).
- **고령 운전자** `[확인 필요: 원문 출처]`: 65세 이상 운전면허 소지자는 2022년 438만여 명이고(경찰청 자료 인용 보도), 국회입법조사처는 2025년 498만 명으로 추산했습니다. 고령 운전자 교통사고는 2025년 4만 5,873건으로 전년보다 8.3% 늘었습니다.

이 운전자들은 대부분 면허를 갖고 정상적으로 운전하지만, **차량이 정보를 주는 방식**이 이들에게 맞지 않아 매번 불편과 위험을 감수합니다.
스마트폰 앱은 차량 상태(벨트·문·방향지시등·좌석)와 내비 경로를 알 수 없어서 이 문제를 풀지 못합니다. **차량 데이터에 접근할 수 있는 인포테인먼트 앱**이어야 해결할 수 있습니다.

## 3. 주요 기능 및 차량 특화 요소

운전자가 처음에 자기 특성을 고르면(여러 개 가능), 앱이 **켤 기능**과 **알림을 전달할 감각**을 정합니다.

| 기능 | 대상 | 차량 데이터 | 전달 방식 |
|---|---|---|---|
| **신호 변화 알림** — 초록불 전환, 늦은 출발 리마인드, 황색, 적색, 긴급 감속 | 색각이상, 주의력 | 영상 + 차속 + 감속도 + 추정 거리 | 신호별 고유 음높이 패턴(진행=올라감, 정지=내려감), 음성, 모양 기호(■▲●) |
| **경로 맞춤 좌회전 신호** — 좌회전 화살표가 켜지면 내 경로가 좌회전인지 직진인지 함께 안내 | 색각이상 | 영상 + NaviHelper 경로 | 음성 + 화살표 기호 |
| **긴급차량 사이렌 감지** — 실내 마이크 소리에서 오르내리는 사이렌을 찾아 "길을 양보하세요" | 청각장애 | 실내 마이크 (기기 안 분석) | 화면 전체 깜빡임 + 헤드업 알림 |
| **소리 경고 시각화** — 벨트 미착용, 주행 중 문 열림 | 청각장애, 저시력 | Vehicle State | 화면 전체 깜빡임 + 큰 글씨 + 헤드업 알림 |
| **방향지시등 깜빡함 알림** — 20초 이상 켜져 있고 30km/h 이상, 안내 지점 근처가 아닐 때 | 청각장애(똑딱 소리를 못 들음), 주의력 | Vehicle State + 차속 + NaviHelper | 화면 깜빡임 / 음성 |
| **내비 안내 카드** — 안내 지점 300m·100m 전 "300m 앞 좌회전 (강남대로)" | 청각장애(음성 안내를 못 들음), 주의력 | NaviHelper | 큰 카드 + 헤드업 알림 |
| **작은 경고등 읽어주기** — 타이어 저압, 어두운데 전조등 꺼짐 | 저시력, 고령 | Vehicle State | 음성 + 1.4배 글씨 |
| **뒷좌석 확인** — 이번 주행에 뒷좌석에 사람이 있었고, 주차하거나 문을 열 때 | 모든 운전자 (아이·반려동물 방치 예방) | Vehicle State 좌석 탑승 | 음성 + 화면 |
| **"? 지금 신호" 질문** — 헷갈릴 때 누르면 현재 신호와 거리를 말해 주고, 확실하지 않으면 그렇다고 말함 | 색각이상 | 영상 + 추정 거리 + 인식 확신도 | 그 신호의 소리 + 음성 (청각장애는 화면) |
| **질문형 첫 설정 + 소리 테스트** — 상황 질문 4개, 차 스피커로 소리 3가지를 들려주고 음역·크기·소리 유지 여부를 맞춤 | 모든 프로필 (특히 부분 난청·고령) | 차 스피커 | — |
| **알림 양 3단계 + 운전하며 익히기** — "보통"은 처음 3번만 소리의 뜻을 덧붙이고 익숙해지면 짧게, 안전 알림은 끌 수 없음 | 모든 프로필 | — | 음성 |
| **알림 배우기 · 다시 듣기** | 모든 프로필 | — | 프로필별 소리·화면 시범 + 한 문장 설명, 큰 다시 듣기 버튼 |
| **주행 요약 공유** — 주차 시 "주행 12분 · 신호 안내 6회 · 긴급 0회" | 고령·장애 운전자와 가족 | 차속 + 알림 기록 (위치 없음) | 화면 + 공유 |

### 안전을 위해 일부러 이렇게 설계했습니다 (차량 특화 판단)
- **안전 우선 비대칭 확정**: 초록불·좌회전 화살표는 5프레임 중 4프레임과 높은 신뢰도가 있어야 확정하고, 빨간불·황색은 3프레임이면 확정합니다. 색각이상 운전자에게 가장 위험한 오류인 "빨간불을 초록불로 안내"를 구조적으로 막습니다.
- **실제 거리와 제동 물리로 판단**: 국내 300mm 등화의 화면 크기로 신호등까지 거리를 재고, 정지선에 서는 데 필요한 감속도(v²/2d)가 2.5 m/s² 이상인데 감속하지 않을 때만 긴급 경고합니다. 멀리 있는 빨간불에는 차분한 안내만 해서 경고가 무시되지 않게 합니다.
- **황색 딜레마 구간**: 반응 시간 1초를 고려해 편안하게 설 수 없으면 "정지하세요" 대신 "급정거하지 말고 주의해서 진행하세요"라고 안내해 뒤차 추돌을 막습니다. 이미 교차로에 들어간 뒤의 빨간불에는 경고하지 않습니다.
- **실패를 숨기지 않음**: 정지선 바로 앞이라 신호등이 화면에서 사라지면 "신호를 직접 확인하세요"라고 말합니다. 침묵을 "아직 빨간불"로 오해하지 않게 합니다.
- **알림 중재**: 같은 순간에는 가장 중요한 알림만 소리·음성·깜빡임으로 전달하고, 긴급 경고 직후 4초는 덜 중요한 알림을 화면에만 띄웁니다. 경고 이상은 항상 전달합니다. 주의력·인지 부담이 큰 운전자를 위한 설계입니다.
- **화면을 보지 않아도 됩니다**: 알림 엔진은 포그라운드 서비스로 돌아가고, 주행 중에는 설정을 숨기고 큰 상태 표시와 다시 듣기 버튼만 남깁니다(CarUxRestrictions 준수).
- **눈부심·광과민성 배려**: 화면 깜빡임은 초당 3회 미만이고 야간에는 밝기를 낮춥니다.
- **필요할 때만 영상 처리**: 신호등을 최근에 봤거나, 저속이거나, 내비 안내 지점 근처일 때만 매 프레임을 처리하고, 그 외에는 초당 2장만 처리해 주행 중 CPU 기준을 지킵니다.
- **알아챌 수 있는 경고 (인지성 설계)**:
  - 알림음이 끝난 뒤 음성이 나와 서로 가리지 않습니다.
  - 소음에 묻히지 않도록 배음이 풍부한 소리를 쓰고, 고령자는 노인성 난청을 고려해 낮은 음역으로 듣습니다.
  - 음성은 "빨간불! 감속하세요!"처럼 짧고 핵심어가 먼저 나옵니다.
  - 위험도가 높을수록 소리가 커지고 깜빡임이 빨라집니다 (안내는 테두리만, 긴급은 5회, 모두 초당 3회 이하).
  - 깜빡임을 놓쳐도 위험이 끝날 때까지 화면 위쪽에 표시가 남습니다.
  - 긴급 경고 시점에 운전자 반응 시간을 넣어, 고령 운전자(1.5초)와 화면으로만 받는 청각장애 운전자(1.3초)에게 더 일찍 알립니다.
- **색에 의존하지 않는 화면**: 실제 신호등과 같은 위치, 정지=팔각형·주의=삼각형·진행=원·좌회전=화살표, 색각이상 친화 팔레트(Okabe-Ito)를 씁니다.

## 4. 주요 사용 시나리오

앱에 시나리오 7종이 들어 있어 에뮬레이터에서 그대로 시연할 수 있습니다.

1. **색각이상 · 정차 후 출발**: 황색에 "정지를 준비하세요" → 정차 → 초록불 전환 0.3초 후 "초록불로 바뀌었습니다"(도→솔) → 3초가 지나도 출발하지 않자 "주변을 확인하고 출발하세요".
2. **색각이상 · 적색 신호 놓침**: 45km/h로 접근 중 74m 앞 적색 → 보통 제동으로 설 수 있으므로 "빨간불입니다. 정지하세요" → 반응하지 않자, 강한 제동이 필요해진 시점(6.5초)에 "빨간불! 즉시 감속하세요" → 제동하면 멈춤.
3. **색각이상 · 황색 딜레마 구간**: 50km/h로 정지선 직전 황색 → "급정거하지 말고 주의해서 진행하세요" → 교차로 통과 후 바뀐 적색에는 경고 없음.
4. **색각이상 · 신호등이 화면 밖으로**: 정지선 바로 앞에 정차해 신호등이 화각을 벗어남 → "신호등이 보이지 않습니다. 신호를 직접 확인하세요" (초록불을 보지 못했으므로 진행 안내도 하지 않음).
5. **색각이상 · 야간 좌회전**: 적색 + 좌회전 화살표, 내비 경로가 좌회전이라 "좌회전 신호입니다. 안내 경로도 좌회전입니다".
6. **청각장애 · 소리 경고 시각화**: 벨트 미착용 출발 → 내비 음성 대신 "250m 앞 좌회전", "100m 앞 좌회전" 카드 → 타이어 저압 → **뒤에서 구급차 사이렌, 화면 전체가 깜빡이며 "길을 양보하세요"** → 방향지시등을 끄지 않아 알림. **소리 없이 모두 화면으로 전달됩니다.**
7. **주의력·저시력 · 야간 도착**: 전조등을 켜지 않고 출발하자 음성 안내 → "90m 앞 목적지"(동시에 나온 알림은 화면에만) → 주차(P)하자 "내리기 전에 뒷좌석을 확인하세요" → 주행 요약 표시.

  - 무작위 600장 신호 검출 정확도 99.7%, 다른 색 오인 0건
  - 거리 추정 오차 중앙값 0.4%
  - 사이렌: wail·yelp·먼 사이렌을 3초 안에 감지하고, 도로 소음·경적·음악·말소리는 감지하지 않음
  - 검출 1프레임 4.3ms(960px, 데스크톱 JVM)
  - 합성 데이터라 실제보다 쉽습니다. 실제 영상과 녹음으로 다시 검증할 예정입니다.

### 실제 도로 검증 (부산 해운대구 센텀시티)
- OpenStreetMap 실제 도로·차로·신호등 위치로 SUMO 교통 시뮬레이션을 돌려, 해운대로 1.76km(신호 12곳)를 주변 차량과 함께 달린 기록을 엔진에 넣었습니다.
- 실제 건물 613개를 높이대로 세운 3D 도시를 만들고, 신호 인식기가 그 3D 운전석 화면을 보고 판단하게 했습니다.
- 결과: 정상 정차 2번은 차분한 안내만, 빨간불을 못 본 장면에서는 운전자가 제동하기 1.7초 전에 긴급 경고 (3D 화면 기준), 초록불 늦은 출발에 리마인드 1회.
- 실제 도로에서 시험하며 거짓 긴급 경고 3가지(먼 신호, 정상 정차, 출발 순간)를 찾아 고쳤습니다.
- 신호 주기는 시뮬레이션 생성값입니다. 본선에서는 실제 신호 현시 데이터 연동을 검토합니다.

### 본선까지 (1차 발표 ~ PT, 약 10일)
1. Vehicle State SDK 호출을 연결하고 Pleos 에뮬레이터 Virtual Console로 벨트·도어·방향지시등·좌석 시나리오를 검증합니다.
2. NaviHelper `getTBTInfo`를 연결해 실제 경로로 안내 카드와 좌회전 판단을 검증합니다.
3. 실제 사이렌 녹음(공개 음원)과 차량 실내 소음으로 사이렌 감지 오탐·미탐을 측정합니다.
4. 에뮬레이터에서 CPU 사용률을 측정하고, 필요하면 처리 폭을 480px로 낮춥니다(1.2ms/프레임).

### 카메라 한계와 단계적 전략
- **1단계 (지금)**: 카메라 없이 Vehicle State + NaviHelper + 실내 마이크만으로 동작하는 기능(청각·저시력·주의력)을 제공합니다. 신호 인식은 합성 영상으로 검증합니다.
- **2단계**: 차량 카메라 API가 열리면 `FrameSource` 구현 하나만 추가해 신호 인식을 실제 영상으로 전환합니다. 블랙박스 영상으로 오인식률(특히 녹색↔적색 혼동)을 측정하고, 필요하면 경량 객체 검출 모델로 교체합니다.
- **대안**: 실시간 신호 정보(신호 현시) 데이터를 위치와 함께 쓰면 카메라 없이도 신호 상태를 알 수 있습니다. `[확인 필요]` 공공 신호 정보 API의 제공 지역과 이용 조건을 확인합니다.

## 6. 기대효과 및 발전 가능성

### 타깃
- 1차: 색각이상, 청각장애, 저시력, 고령 운전자와 그 가족 (차량 구매 시 가족이 설치해 주는 경우 포함)
- 2차: 모든 운전자 (뒷좌석 확인, 방향지시등 깜빡함 알림은 누구에게나 유용)

### 예상 MAU (가정 기반 추정)
`[확인 필요]` 아래 수치는 모두 가정이며, 근거와 함께 고쳐 쓰세요.
- Pleos Connect 탑재 차량: 2027년 말 50만 대 (가정)
- 대상 운전자 비율: 색각이상 약 2.5%(남녀 평균) + 청각장애 약 0.9%(44만 명 / 인구) + 고령 운전자 약 10%(가정) ≈ 13%
- 대상 중 설치율: 15% (가정)
- **예상 MAU ≈ 50만 × 13% × 15% ≈ 1만 명**

### Retention
- 설정 후에는 **매 주행 자동으로 동작**하는 백그라운드 서비스라 따로 열 필요가 없습니다. 장애 특성은 바뀌지 않으므로 한번 맞으면 계속 씁니다.
- **질문형 첫 설정과 소리 테스트**로 처음부터 내 귀에 맞는 알림을 받고, **알림 배우기**와 **운전하며 익히기**(처음 3번만 소리의 뜻을 덧붙임)로 첫 사용 장벽을 낮추고, **알림 중재·거리 기반 판단**으로 알림 피로를 줄여 삭제를 막습니다.
- **주행 요약**("긴급 경고 없이 안전하게 주행했습니다")으로 매 주행 성취감을 주고, 가족과 공유하며 다시 쓰게 합니다.

### 확대 계획 · 사업 모델
1. Pleos App Market 출시 → 장애인 단체·운전 재활 기관과 함께 사용자 검증
2. **B2B 연계**: 주행 요약(위치 없는 안전 지표)을 바탕으로 고령 운전자 가족 안심 서비스, 운전 재활 기관 리포트, 보험사 안전운전 특약과 제휴 (본인 동의 기반)
3. 차량 카메라·HUD·햅틱(시트·스티어링) API가 열리면 출력 채널 확장 (청각장애 운전자에게 진동 알림)
4. 경적 감지, 신호 잔여시간 안내로 기능 확대
5. 렌터카·카셰어링 차량 기본 탑재 (내 차가 아니어도 같은 설정을 계정으로 불러오기)
6. 접근성 규제·인증이 강화되는 해외 시장으로 확대
